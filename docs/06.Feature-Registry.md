The former “step3 onward — unallocated” range was replaced on **2026-10-27**, when the owner established the implementation order and allocated `step3`–`step11` in it. The sequence, the gate and the approval boundaries are owned by [11.Business-Module-Roadmap](11.Business-Module-Roadmap.md); each module's scope and dependencies by [12.Module-Specifications](12.Module-Specifications.md).

**Allocation is not authorization.** A row here means the module has a number and a place in the order. `step4` and `step5` required their own owner approval before any code and both now have it (2026-10-28); `step6`–`step11` additionally wait for gate `G1` (the Foundation Review). `step3` was authorized on 2026-10-27 and its child identifiers (`step3.a` … `step3.f`) are recorded here now. Each remaining module's children are recorded when that module's plan is approved, following the hierarchy in [Project Rules](00.Project-Rules.md).

**No dotted sub-identifiers exist.** `step2.1`, `step2.2` and similar labels are not repository identifiers and must not be created; ordering is expressed by the allocated number alone. `step2.NextFeature` in older naming examples is a placeholder, never a name.
