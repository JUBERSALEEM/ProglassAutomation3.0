## 5. Fixes made in this audit

### 5.1 `step5` behaviour tests — G1-08 (the one finding fixed outright)

`step5` was the only foundation module with no behaviour tests, and it is the
module that writes into another module's table. It now has three files and one
entry point:

| File | Covers |
| --- | --- |
| `step5.f.4.ProjectBehaviourChecks.cs` | numbering (`NextNumber` gaps, padding, malformed input), the number shape, required name, legal statuses, normalisation, and **migration 1017 on an isolated database** (table, both link columns, the unique index, the legacy placeholders, and a second initialisation being a no-op) |
| `step5.f.5.ProjectBehaviourChecks.Link.cs` | round-trip and "restart" (a fresh repository reads the stored values), update-in-the-same-row, close/re-open, closed-number refusal, refused-save-adds-no-row, duplicate number refused by the database, and the inquiry link: attach, **whole-row comparison**, attach-twice refusal, attach to a missing project, candidate list, detach, double-detach |
| `step5.f.6.ProjectBehaviourChecks.CrossModule.cs` | deactivating a client leaves the project's `ClientId` intact, and no delete path exists (reflection on the interface + a source scan for `DELETE FROM`) |

Run them on Windows/.NET 8:

```
dotnet run --project step5.ProjectRecords\step5.f.tests\step5.f.ProjectTests.csproj -- --behaviour
```

Exit code 0 = every check passed. **They have not been executed here** — recorded as
NOT RUN in §6, not as passing.

### 5.2 The whole-row comparison, and why it is the important one

`step5.f.5` reads every column of the inquiry row before the attach and after it,
then fails if anything other than `ProjectRecordId` changed. That is the assertion
the G1 review asked for, and it is the difference between "the link works" and "the
link cannot damage an inquiry".

### 5.3 The tests are themselves gated

`step5.f.1` gained rule 23: the assertions must still exist (anchored on the
assertion text, not on a symbol name), every declared `Check*` must be invoked from
`Run()`, the harness must still dispatch `--behaviour`, and the chain tip must be
*derived* from `AppSchemaMigrations` rather than written as `1017` (the existing
`step1.d.6` gate caught that literal, and it was fixed rather than waived).

**Mutation-tested: 8 of 8 deliberate breakages caught** — deleting the whole-row
baseline, deleting a legacy-value assertion, deleting the detach assertion, making
numbering count-based, removing the dispatch, skipping the client deactivation,
dropping the no-DELETE rule, and un-invoking a check from `Run()`.

## 9. The migration blocker, stated exactly

G1-02 requires 1017 to be shown preserving a **real pre-1017 database**. It has
not been shown, and this audit did not produce it:

- the sandbox has no .NET SDK, so the harness cannot run here;
- on the owner's machine the run stopped before the migration: the last attempt
  reported `FAIL: no database at D:\G1\run-20261029_180350\inquiries.db`, which is
  the harness refusing a copy that was never created — `Copy-Item` had no source
  file at the path it was given. That is a missing file, not a migration result;
- a copy already at `user_version = 1017` proves nothing, and the only report on
  `D:\G1` is still the `NOT RUN` no-op from `17:21`.

**This is a release blocker for upgrading an existing customer database**, because
1017 is the migration that alters every live `inquiries.db`. It is not a blocker for
the rest of this audit, which is why the audit continued past it as instructed.

To close it, exactly one of these must exist:

1. a copy of a database **below** 1017 (a `MigrationBackups\inquiries_pre_v1017_*.db`
   written by the runner during a previous upgrade), then
   `dotnet run --project step5.ProjectRecords\step5.f.tests\step5.f.ProjectTests.csproj -- "<copy>"`;
2. or a frozen copy at 1017 with `--rewind-1017`, which the harness refuses whenever
   project rows or linked inquiries exist.

The first is a genuine legacy test. The second is a rewind of a current database.
Both are described in `docs/18` §5; neither has happened yet.
