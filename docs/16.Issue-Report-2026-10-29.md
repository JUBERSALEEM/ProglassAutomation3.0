## 2. Text without a heading type

A heading written as `FontSize="{FontSizeSection}"` + `FontWeight="{FontWeightHeading}"`
looks like a heading but is not one: a theme that restyles `SectionHeading` never
reaches it (Swiss sets its `Foreground`; all three themes own its margin and its
place in the scale). These were hand-copying the heading's settings.

| Where | What was wrong | Status |
| --- | --- | --- |
| Company profile | Page heading hand-written. | **Fixed.** `Style="{DynamicResource SectionHeading}"`. |
| Inquiry inbox | "Website connection", "Website deliveries", and the "No website deliveries yet" empty state — all hand-written. | **Fixed**, same treatment. |
| Inquiry list | "No inquiries match the current filters" — hand-written with an inline `TextPrimary`. | **Fixed.** |
| Users, first-run form | Five field labels repeated the same three setters inline; no `UserFieldLabel` style existed although step2 has `ClientFieldLabel`. | **Fixed.** One `UserFieldLabel` style, five uses. |
| Inquiry inbox counters (ready / ingested / failed) | Section size and weight, but bound to a figure with a status colour. | **Left alone** — a count is a figure, not a heading. The Theme Studio's own metric cards do exactly this. |
| Theme Studio (2 cases) | Same pattern. | **Left alone** — out of scope by standing instruction (do not restyle Theme Studio). |

## 3. Columns too narrow for their own content

| Column | Width | Needed | Effect | Status |
| --- | --- | --- | --- | --- |
| `UpdatedText` (project register) | 130 px fixed | ≈145 px — `yyyy-MM-dd HH:mm` is 16 mono characters plus 16 px padding | every timestamp clipped to `2026-10-28 09:…` | **Fixed** → `Width="Auto"`. |
| `InquiryNumber` (two project panels) | 100 px fixed | ≈117 px — `INQ-2026-0001` is 13 characters plus padding | every number clipped to `INQ-2026-0…` | **Fixed** → `Width="Auto"`. |
| `ReceivedText` (linked inquiries) | 90 px fixed | ≈100 px — `yyyy-MM-dd` plus padding | tight, could clip on larger fonts | **Fixed** → `Width="Auto"`. |

Only the project register used fixed pixel widths; the Inquiry, Client and User
registers size with `*` and a minimum, which is why they were never clipped.

`Auto` rather than a bigger number because the mono font and the font scale are
theme tokens — a fixed width that fits today's 13 px would clip again the moment
the scale grows.

## 4. One functional bug found during the cross-check

`SelectedErrorText` was **`private`** in `InquiryInboxViewModel` but bound in
`InquiryInboxView.xaml`. WPF cannot bind a private member and does not report an
error at build time: the binding fails silently at runtime, so **the reason a
website delivery failed has never been displayed**. Now `public`.

The gate that should have caught this was asserting the property *was* private —
it had frozen the defect in place. Inverted: it now requires `public` and
requires the view to keep binding it.
